what the curve means

no measurable ceiling: at 16 workers the curve is still 85% efficient and the fitted 88x sits well past the 13.7x we actually measured. Read it as a lower bound; sweep another doubling if you need to know where it bends.

why

Every mode returned the same result — checksums match, so the comparison is between schedules, not between different answers.
Threads gave 13.55x: waiting on I/O costs no CPU, so the GIL is not the bottleneck. Concurrency is enough; you do not need processes.
async note: true coroutine suspension, no OS thread per request.
